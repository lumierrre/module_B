# Статический аудит банковского API

## 1. Назначение и исходные материалы

Цель проверки — выявить недостатки в обработке переводов, доступе к истории операций и конфигурации сервисов. В этой папке собраны предоставленные результаты ранее выполненного анализа Semgrep и ручной проверки. Новый запуск при подготовке комплекта не выполнялся. Исходные файлы приложения и машинные отчёты не изменены.

Проверены контрольные суммы девяти файлов из `microservice.zip` и четырёх файлов отчётности: все совпадают с предоставленным исходным манифестом. Это подтверждает совпадение байтов, но само по себе не удостоверяет автора или дату запуска сканера.

### Решения по итогам триажа

- A02 и A03 относятся к одной гонке между проверкой остатка и списанием. Для её обработки необходимы атомарная операция либо блокировка строк и конкурентные тесты.
- A04 и A05 фиксируют два места хранения одного секрета. A06 увеличивает поверхность атаки при сетевой доступности БД. Необходимы управление секретами, ограничение привилегий и сетевая изоляция.
- Для A07 и A08 необходима проверка фактической сетевой доступности, ACL и защищённости соединений.
- A09 и A10 — недостатки работы с кешем. В текущем коде заполнение кеша не реализовано, поэтому последствия зависят от наличия ключей.
- A11 и A12 не подтверждают SQL Injection: в SQL-строку подставляется внутренний номер параметра, а `search` и `limit` передаются через `params` в `asyncpg`. Информационные записи сохранены без удаления.

## 4. Отдельная проверка объектного доступа

**ID:** `manual.bank.idor-bola` · **CWE-639** (связана с CWE-306) · **ERROR** · источник: ручной статический анализ.

В `app/security.py:3–13` идентичность определяется по `X-User-Id`. В `app/main.py:13–24` этот идентификатор должен передаваться обработчикам. Проверка принадлежности исходного счёта (`app/crud.py:5–16`) и фильтрация истории (`app/crud.py:43–66`) используют переданное значение. Следовательно, при работоспособном API объектный контроль опирается на недоверенную идентичность. Самостоятельный обход проверки владельца без этой первопричины не установлен.

Для банка это риск раскрытия истории другого клиента и несанкционированных переводов. Рекомендованы проверенная идентичность из токена, объектная авторизация и отрицательные тесты с двумя независимыми пользователями. Динамическая эксплуатация не проводилась; в предоставленных исходниках есть несовместимые импорты, мешающие штатному запуску.

Ручная запись отделена от автоматических находок. Проверено, что первые 12 записей дополненного JSON совпадают с оригиналом, а остальные поля отчёта сохранены. Реестр `manual-findings.json` содержит 12 ручных наблюдений и рисков, включая пересечения с автоматическими записями. Складывать эти количества для подсчёта уникальных уязвимостей нельзя.

Для повторного сканирования установите Semgrep и Python 3. Из корня проекта выполните:

```bash
bash security-tools/run_sast.sh
```

Новый результат попадёт в `static-analysis/generated/run-.../`; предоставленные отчёты в `reports/` не перезаписываются. Скрипт добавляет отдельную ручную находку IDOR для исследуемой версии кода. При изменении исходников её актуальность и номера строк следует проверить повторно. Чтобы выполнить только автоматическую проверку:

```bash
ADD_MANUAL_IDOR=0 bash security-tools/run_sast.sh
```

Для проверки целостности из корневой папки проекта (GNU coreutils):

```bash
sha256sum -c static-analysis/reports/SHA256SUMS
```

В новом манифесте изменены пути к четырём отчётам, их контрольные суммы сохранены. Две записи о модели угроз из старого манифеста не перенесены, поскольку точные файлы модели и её нативного PDF в данном наборе не предоставлены для проверки. Хеш конфигурации добавлен для будущего контроля целостности; это не подтверждение того, какая именно конфигурация применялась при предыдущем запуске.

## 6. Итог

Приоритет обработки — идентификация клиента и объектный доступ, целостность денежных операций, защищённость хранилищ. Результаты должны пройти повторную проверку после внедрения мер. В рамках настоящего комплекта исправления не вносились, новый SAST и динамические тесты не выполнялись.
